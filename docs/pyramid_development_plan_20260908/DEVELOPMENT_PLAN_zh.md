# Pyramid / Pyraimd 开发执行计划

版本：1.0；日期：2026-09-08。用途：交给负责实现的开发者或 coding 智能体执行，再由研究负责人审阅。本文提出的是目标设计；除明确标为“已有”的内容外，命令、模块、接口和验收结果均尚未实现或验证。

## 1. 要做成什么

**Pyramid 是以 ASE 为基础、面向材料研究的自适应原子模拟框架。** 它把结构、参考求解器、快速势、误差预测、参考调度、模型修正、动力学和计算记录连接起来，让研究人员用一个小配置或一段 Python 程序完成可恢复、可检查的计算。

产品名保持 **Pyramid**，全称保持 **Python wrapped Ab initio Molecular Dynamics**。这一轮保持 Python 包名 `pyraimd2` 和两个现有命令入口 `pyramid`、`pyraimd2`，避免把迁移成本花在改名上。

ASE 已提供 Atoms、Calculator、结构操作、I/O、优化器和多种 MD 算法。Pyramid 应直接复用这些能力，把独特价值放在：

1. 在同一原子状态上连接不同精度的模型和求解器。
2. 根据物理误差信息选择参考计算、探针、传播和模型更新。
3. 记录实际使用的力、误差影响、完整成本以及恢复所需的状态。
4. 让新的科研方法以可替换模块接入，不需要重写整个软件。

这是一条有明确分工的生态路线，而不是追求另写一套 ASE。ASE 的 Calculator 接口已经覆盖很多电子结构与 MLIP 软件，优先通过它扩大兼容性。[ASE Calculator 官方文档](https://docs.ase-lib.org/ase/calculators/calculators.html)

### 第一批目标用户与完成体验

- 做周期材料 MD 的研究人员：配置结构、MACE 和 QE，运行、停止、续算，导出 ASE 能读取的轨迹。
- 做表面／缺陷计算的研究人员：固定部分原子，先优化，再进行固定晶胞 MD，并能检查参考调用集中在哪些构型。
- 开发新模型或方法的研究人员：换一个 ASE Calculator、参考引擎或误差策略，复用同一套记录、成本比较和验证工具。

用户不应为了运行一个普通算例去改库的源码、理解内部回调顺序，或从数据库里手工拼出续算状态。

本计划检查的公开基线提交：`362696a86793b199d696546522b2085937262e55`；软件版本 **0.3.0**。同一仓库中 `force-error-repro-v1.2.0` 是论文复现包的固定标签，不是软件版本。

当前研究工作区中的公开软件检出位于 `.release/pyramid/`。执行者可以用它确认内容，但建议从公开仓库建立独立开发检出和功能分支。开始时报告实际基线 SHA；如果公开主分支已经前进，先检查相关差异，不强行退回或覆盖新工作。

**修改对象是软件仓库，不是已投稿论文。** 保留论文复现标签、数值目标和已提交文件。新实验应有自己的目录、配置及结果；不要通过更新旧预期值让新的实现“通过”。本轮计划编制不启动开发或云端计算。

完成 0.4.0 不依赖私有研究目录中的脚本；公开源代码、本文契约及执行者自行构建的小测试足够。旧科研记录只用于后续方法比较与背景追溯。

- `src/pyraimd2/engines/`：Engine、PySCF、QE 与通用 ASE 引擎。
- `src/pyraimd2/surrogate/`：单势、委员会、ASE 包装及训练协议。
- `src/pyraimd2/energetics/`：方向响应、预测、残余功、独立检查计数界。
- `src/pyraimd2/loop/energetic.py`：锚定、两尺度探针、当前离散力评估的准入、独立检查及 ASE Velocity Verlet 接入。
- `loop/online.py`：标签回调与定期更新入口。
- `store/store.py`：ASE 数据库，保存基势、参考标签及真正驱动力。
- 原 switching、scheduled、threshold、conformal 工作流及单元测试。
- 0.3.0 已有 Linux CPU 验证记录：170 项软件测试、解析示例及短分子算例。它是既有证据，不代替新代码的测试。

### 当前最影响可用性的缺口

1. `EnergeticRunner.resume` 明确未实现。现有数据库轨迹不能直接视为完整 energetic 续算文件。
2. 当前 energetic runner 限于固定晶胞、无约束 NVE；计算器内仍用评估索引和固定步长组织时间。不能直接套入任意 ASE 优化器或恒温算法并假定语义相同。
3. CLI 目前只打印版本和示例提示，缺少配置、运行、续算、检查和导出入口。
4. 模型更新主要通过回调报告变化；缺少统一、持久化的模型身份、更新提交和回退机制。
5. 引擎返回墙钟时间，但 summary 主要汇总成功参考调用次数；失败、探针、训练、缓存和实际资源使用尚未形成完整账本。
6. QE 适配器是特定固定晶胞输入路径，当前 writer 写入 D3；通用后端能力、能量口径和配置校验仍需产品化。
7. 对外示例以解析／分子场景为主；尚需完整的周期体相、固定层表面工作流及清楚的支持矩阵。

## 3. 版本目标与停止条件

### 0.4.0：第一版可供外部用户试用的稳定工作流

本轮执行范围为下文 **WP00–WP09**。先修复已定位的正确性问题，再建立稳定工作流。完成标志是：

- 可以用配置进行单点、固定模型结构优化、固定晶胞 NVE；支持 reference-only、surrogate-only 和明确支持的 adaptive MD 模式。
- energetic NVE 可以从完整步边界续算；冻结模型和受支持更新器的状态均可恢复。
- 最小核心仍只需 NumPy、ASE 和标准库；不运行模型推理也能验证主要运行机制。
- 能替换 ASE 后端，并有 QE＋MACE 的周期体相与固定层表面案例。
- 每个新案例都有输入、后端版本、命令、预期检查和完整成本；不要求先得到论文级加速比。
- 支持固定原子约束 `FixAtoms`，定义并测试自由坐标的力预算及真实驱动力；复杂约束留到后续。
- 有一条真实的标签收集—模型更新—重新锚定—保存／恢复演示。生产可恢复模式只接受已实现状态导出的更新器。
- 关键错误会停止或进行有记录的有限重试，不会把失败结果当成成功标签。

上述条件通过即结束第一轮开发，形成候选发布和回报。不要为等待新 AI 方法、更多求解器或长时输运算例而无限延长。

### 0.4.1：恒温动力学与兼容性扩展

执行 WP10：固定晶胞 Langevin NVT、随机状态恢复、正确的温度自由度及热浴作用记录。随后按真实用户需求增加 CP2K／VASP 配方。它不阻塞 0.4.0。

### 0.5.x：响应修正与学习实验平台

执行 WP11–WP12：保守响应修正、响应复用、可替换的学习与探针策略。先进入 experimental 命名空间；以新的前向物理证据决定是否成为默认算法。

NPT、复杂约束、QM/MM、学习传播器、自研电子求解器、分布式异步服务属于后续路线。0.4 保留必要边界，暂不为这些方向搭建空框架。

## 4. 架构与技术选择

### 4.1 五层分工

1. **用户入口**：Python API、TOML 配置、CLI、材料配方。
2. **工作流与动力学**：单点／优化／MD、真实时间、步边界和运行状态。
3. **自适应方法**：参考请求、误差预测、修正模型、检查与更新。
4. **后端**：Engine、Surrogate、ASE 适配、外部程序执行与模型文件。
5. **运行服务**：数据记录、checkpoint、成本、版本、导出。

`energetics/` 保持纯数值层，不依赖文件系统、CLI、SSH、Slurm 或深度学习框架。上层可以组合它，数值层不反向调用上层。

### 4.2 新模块的最小建议

在现有 `src/pyraimd2/` 内渐进加入：

- `config.py`：配置 dataclass、解析和校验；先不建大型配置子系统。
- `cli.py`：命令入口。
- `runtime/`：评估上下文、状态、checkpoint、模型身份、执行记录。
- `workflows/`：单点、固定模型优化、MD 的编排。
- `backends/registry.py`：工厂和能力注册；现有 engines、surrogate 文件保留。
- `analysis/run_summary.py`：成本、路由和误差报告。
- 后续 `experimental/corrections/`、`experimental/probes/`：研究模块。

文件名可按实现调整，但职责必须保持。不要第一步重命名所有旧模块，也不要创造与 EngineResult、SurrogatePrediction 平行的第三套不兼容结果。

### 4.3 依赖与配置

- Python 继续以 3.12 为下限。配置使用标准库 `tomllib`＋dataclass；CLI 优先 `argparse`；插件发现用 `importlib.metadata`。
- 用户默认用 TOML，单位直接出现在字段名中。先不同时维护 YAML、JSON 和 Python 三套配置语义。
- MACE、PySCF、RDKit 等保持可选依赖和延迟导入。导入 `pyraimd2`、查看帮助、读取运行目录不应自动加载 Torch 或下载模型。
- Python 用户可直接传入配置好的 ASE Calculator。CLI 的任意后端通过已安装的注册工厂接入；普通配置不使用 `eval` 或任意表达式执行。
- 实际算法按后端能力和物理设置工作，不按 Si、W、某个势名等材料标签分支。材料差异放在配方、模型和配置中；普适性通过可替换的能力契约实现。
- 不增加 Web 服务、GUI、消息队列、容器集群和自定义任务调度器。先让一个 Python 进程管理一个可靠的运行。

### 4.4 ASE 接入原则

Atoms、CIF/POSCAR/extxyz/trajectory、优化器和 MD 积分实现优先来自 ASE。优化只允许固定模型或 reference-only；不能把带时间准入和模型切换的当前 energetic Calculator 直接塞进 BFGS，制造并不存在的固定势能面。

ASE 的普通结果缓存只涉及计算器状态，不能覆盖 Pyramid 的模型版本、策略状态、锚点与随机检查。ASE CheckpointCalculator 可以启发昂贵单点评估复用，不能替代整个自适应 MD 的 checkpoint。[ASE checkpoint 文档](https://docs.ase-lib.org/ase/calculators/checkpointing.html)

## 5. 不可破坏的物理与运行契约

### 5.1 单位、能量与后端能力

- 对外位置 Å，能量 eV，力 eV/Å，时间 fs，温度 K；stress 使用 ASE Voigt 顺序和符号。
- 保留原子顺序、晶胞、PBC、质量、初始电荷／磁矩和约束身份。速度与动量不可混用；进入 ASE 时只转换一次时间单位。
- 元数据至少区分 `energy`、`free_energy`、`unknown`，并记录报告能量是否与力一致。后端能返回一个能量不等于该能量的梯度就是它返回的力。
- 对不保守或能量口径未知的快速模型，可支持明确定义的 forces-only MD 和力诊断；依赖保守势的 endpoint work 和方向系数解释应关闭或标为不可用。不要把未知能力强写为真。
- 外部 SCF 失败、不完整力块、非有限数组、原子数不符均不能生成合格标签。保存失败原因和已有成本。

### 5.2 物理时间与评估身份

增加显式 `EvaluationContext`，至少包含 `run_id`、`step_id`、`evaluation_id`、`phase`、`physical_time_fs`、`model_id`。它由 workflow／integrator 提供。

`step_id` 计完整积分步；`evaluation_id` 计逻辑力评估；`physical_time_fs` 来自真实积分时间，三者不混用。探针、单点、优化器试探点不推进 MD 时间。重复读取同一状态的能量和力不增加物理步、检查次数或参考请求；坐标恰好不动的新物理步仍是新的时间事件。

保留现有直接 Calculator 用法的兼容层，说明其固定步长假设；新的受支持 workflow 必须使用显式上下文。不要默默改变旧接口的时钟含义。

### 5.3 冻结、检查、更新的顺序

一次逻辑评估按以下顺序完成：

1. 固定构型、模型／参考设置、锚点和已有响应。
2. 算出候选力和能量，作准入决定，保存决策依据。
3. 对已接受候选独立抽取检查；拒绝或按计划请求参考的分支另记用途。
4. 在外部计算前持久化冻结提议及检查抽样；如需参考，取得合格标签。失败重试使用同一个评估身份和同一个检查抽样，不重新抽签。
5. 记录候选、实际驱动力、观测误差及本次结果，提交逻辑事件。
6. 完整积分步完成后形成可恢复状态；新标签进入更新队列。只在受控边界发布新模型，并在下一次新提议前重新建立适用锚点／响应。

被检查的接受力不能在事后被参考力替换而继续计入“被接受的候选”。`on_label` 的副作用必须有显式状态；模型更新不能发生在当前 work 段尚未按旧模型结算之前。

独立检查计数的是其预先定义的接受评估流，不是所有 SCF、探针或重试。检查概率、倾斜参数和失败概率是检查段的固定设置；普通 resume 不更改它们。确需更改时新建检查段并分别报告，不能把旧计数塞进新参数公式。

### 5.4 两种缓存必须分开

- **数值标签缓存**：相同后端和参考设置下的同一构型，可以复用能量／力。
- **决策缓存**：只可复用同一逻辑 evaluation 的候选和决定，不能仅按几何复用。

标签键包含原子、晶胞/PBC、相关电荷／自旋、计算参数、赝势／模型身份、能量口径及需要的属性。保守力的标签键通常不需要速度；决策键还需要时间、动量、锚点、模型及策略代次。初版用精确规范化值和哈希，不用几何近邻近似匹配。

缓存查找本身不产生独立抽查。每个新的已接受 evaluation 仍按既定概率独立抽取检查；若检查被选中，可以使用参考设置、构型及能量／力口径完全匹配的有效缓存标签，检查正常计数，新增物理 SCF 执行数为零。重读或恢复同一个 evaluation ID 不重抽、不重复计数。几何相同的新接受评估与同一评估的重放必须区分；`p=1` 时即使原子静止且标签全部命中缓存，也应检查每个新的接受评估。外部状态不透明且无法可靠标识的后端，默认关闭跨评估标签缓存。

### 5.5 周期坐标和约束

动力学内部保留连续展开坐标；输出可另给 wrapped 坐标。不能在累计功前通过最小镜像“猜”跨胞历史；不能把同一原子跨边界误判为大位移。

`FixAtoms` 的第一版明确支持集合。固定自由度从探针方向和动力学误差范数中投影出去，并同时保存原始全原子残差作为诊断。默认 force budget 控制真正传播的自由坐标；报告必须写明。若用户要控制全原子误差，使用独立模式，不能静默更改定义。

固定原子的位移为零，其路径做功为零；支撑层可以承受反力。不要把自由体系的总动量守恒要求机械地加到受外部约束的表面。复杂 RATTLE 约束、运动约束或变胞工作在支持之前明确拒绝。

## 6. 运行目录和恢复设计

一个运行目录包含：

- `config.toml`：用户原配置。
- `resolved_config.json`：实际生效参数、软件版本和单位。
- `manifest.json`：运行身份、配置摘要、输入和后端身份。
- `trajectory.db`：ASE 数据库视图，保留既有标签和 driving-force 格式。
- `events.jsonl` 或等价的单写者结构：评估、任务和模型更新事件。初版只选一种权威事件存储，不同时维护多个竞争真值。
- `checkpoints/<generation>/state.json`、`arrays.npz`、`manifest.json`：完整步快照和校验。
- `models/<model_id>/`：不可变模型工件与元数据。
- `calculations/<evaluation_id>/<purpose>/<attempt>/`：独立外部计算目录。
- `summary.json`、`summary.csv`、可选 ASE 轨迹导出。

### checkpoint 必须包含的状态

1. Atoms 数组、连续坐标、PBC、晶胞、质量、动量、支持的约束。
2. 积分器完整步状态、真实时间、已提交评估 ID、该状态可复用的驱动力。
3. 锚点位置、参考／基势能量和力、常数校正、segment ID。
4. 方向向量、响应、探针尺度、域参数及每方向的连续准入前缀状态。
5. 策略状态、待重新锚定原因、检查计数和随机发生器完整 bit-generator 状态。
6. 模型身份和工件引用、更新器计数、训练／标签队列消费位置；需要时保存优化器及相关随机状态。
7. 与 checkpoint 对应的最后一个已提交事件编号及 schema 版本。

不能只保存随机种子，不能用数据库最后一行的半步动量当完整步动量。当前 Store 是力评估记录，不是完整步 checkpoint 的替代品。

### 事务与失败

完整 generation 写入临时目录、刷盘、写校验清单，再原子更新 latest 指针；保留上一份可用 generation。采用一个进程／一个数据库写者，不在多个 MPI rank 上同时写同一个 SQLite 文件。

崩溃后先以最后有效完整步 checkpoint 为恢复基点，再从其事件游标按原逻辑顺序重放已持久化的后续事件。仅复用其后的参考标签不足以恢复运行：必须复用已冻结提议、抽查结果和驱动力，并恢复对应的 RNG 后状态、计数、标签消费位置及模型激活顺序。已提交事件不重复追加，不重新抽签；下一个尚未发生的检查从恢复后的随机流继续。

事件协议必须记录积分阶段和完整步完成边界，使受支持的确定性 NVE 积分器可用已保存的力重放到一致状态；也可保存等价的完整步状态记录。不能由一行力评估猜出是否已完成 half-kick。尚未提交完整步的事件保留其阶段，用于恢复重放；在完整步成功提交前不作为已完成轨迹导出。模型更新只能影响其激活边界之后的新提议，已经用于积分子步的冻结驱动力不能被事后替换。

更新完成记录、更新器状态和不可变模型工件身份必须先持久化，再激活模型。恢复时在原边界应用已完成的更新，不重跑已经完成的 callback 或训练。更新是否完成或其工件身份不可确定时，停止自动恢复并报告待处理状态；普通回调如不能满足这一协议，应明确不支持可靠续算。

SIGINT／调度器终止信号请求在最近可完成的步边界保存后停止；来不及完成时使用上一代 checkpoint。信号处理只置标志，实际文件提交在正常控制流执行。长 SCF 的中止和子进程状态进入 attempt 记录，不把半步状态发布为完整步。

实际已花费的计算成本不因轨迹回滚而消失：**轨迹逻辑计数可恢复，物理执行成本账本只追加。** 外部任务是否完成若不可判定，记录为 pending/unknown 并查询输出或调度状态；不要声称外部执行必然 exactly-once。

两种显式操作：

- `resume`：同一物理设置、模型链和随机流继续；只允许输出频率等不改变算法的字段变化。
- `fork`：从指定完整步启动新运行，保留 parent ID；改变物理／策略参数时使用，重新定义模型和检查段。

第一版只保证受支持 runner、已知配置及已实现状态导出的后端／更新器可恢复。任意 Python 闭包不能靠 pickle 被自动宣布为可靠续算。

## 7. 工作包与逐项验收

### WP00 — 已定位的基础正确性修复（P0，最先执行）

以下是本轮静态代码核对发现的具体问题；尚未运行新复现测试。执行者先补能暴露问题的小测试，再做局部修复，不进行全仓库重构。

1. **ASE 适配的约束能量口径**：`AseEngine.compute` 使用未投影力，但取能量时仍允许 constraint adjustment；有势能的约束会让能量和力不成对。后端统一返回原始物理能量／力／stress，约束由 workflow 明确施加一次。MaceSurrogate 同步使用一致的属性、复制及校验规则。用一个带能量项的约束测试，单独的 FixAtoms 测试不足以发现这一问题。
2. **QE 目录与相对路径**：`QeEngine.compute(atoms, label="step")` 在普通协议调用中不断落到同一目录；`_attempt` 同时改变 cwd 并传入含 run_root 的相对输入路径。为连续计算分配唯一目录，规范路径；用读取真实输入文件的 fake executable 测试，不只 mock subprocess 返回值。
3. **QE 密度回退**：当前失败后删除 `tmp`，但再次 `_attempt` 仍使用 `startpot_file=True`。回退必须生成明确的 atomic-start 输入，同时保留原失败目录和诊断；测试第二次输入实际改变，而不只是“调用了两次”。
4. **QE 输出成组解析**：目前最后一个能量、所有力行和第一个 stress 可能被拼成一份结果；匹配到 D 指数后 `float` 也未转换。选择同一个完整 SCF 结果块，处理 D/E 指数及原子数／有限性，保留现有正确样例。
5. **委员会恢复与设备**：`CommitteeSurrogate.load_state_dict` 没有完整验证训练 recipe、成员状态数量及能量偏移长度；加载前校验，在失败时不部分修改现有模型。委员会当前 CPU 数据路径不能因为接收 device 字段就宣称 GPU 可用；0.4 可明确只支持 CPU 委员会，单 MACE GPU 路径单独声明并测试。
6. **缓存前的物理状态检查**：质量或约束单独变化可能绕过 `calculate` 内的检查。获取已缓存属性和开始 Verlet drift 前均验证不允许的变化；完整模型代次和决策缓存机制随后在 WP01 实现。

**验收**：每个问题有一个修复前能暴露、修复后通过的定向测试；不调用昂贵 DFT。预检查错误在推进原子之前报出；已经进入积分子步的运行时失败不提交成功标签或完整步，但保留失败诊断和已付成本，由 WP03 恢复到最后完整 checkpoint。先运行相关现有 suites，再合入这些小修复。

### WP10 — 固定晶胞 NVT（0.4.1，后续）

选一种 ASE 已实现的 Langevin 算法，记录具体版本与完整随机状态。先在 reference-only/fixed surrogate 上接通，再接 adaptive。积分器的随机子步、力评估阶段和温度自由度必须进入上下文与恢复设计；不能仅替换类名。

在解析谐振体系检查平衡分布及时间步效应；在相同随机流下对比连续／恢复轨迹。避免直接依赖已弃用的 `fixcm=True` 行为；依据目标 ASE 版本和自由度定义处理质心约束。[ASE MD 官方文档](https://docs.ase-lib.org/ase/md.html)

能准确计量热浴子步时分别输出 bath work 和积分误差；如果只保存总参考能变化与 residual work，则把剩余量命名为“未分解的热浴／离散项”，不能当作纯积分漂移。NVE 中的能量判据不直接套成 NVT 保证。

### WP11 — 保守响应修正（0.5 experimental，后续）

按第 10 节实现对称局部修正及强基线，默认关闭。先离线、再解析前向、再小周期前向；修正配置和模型状态使用已有 registry、checkpoint、成本与检查体系，不另起一个无法兼容的实验 runner。

### WP12 — 响应复用、学习与求解器状态（研究扩展，后续）

为 probe strategy、response memory、correction model、reference warm start 提供具体实验接口。先完成一个真实实现再抽象公共接口。学习模块作为可选包；输入输出和失败退回规则与非学习模块一致。

执行者可以完成方法所需的软件支撑，不自行放大科学结论、重定义成功指标或启动无限材料搜索。科研比较按第 10 节节点回报，由研究负责人决定继续。

## 8. 拟议配置与使用体验

下面是**目标格式，不是现有 0.3.0 可运行文件**。实现者应最终用测试中的真实可运行配置替换它。

```toml
schema_version = 1

[task]

[structure]

[dynamics]

timestep_fs = 0.5
steps = 20
temperature_K = 300.0
velocity_seed = 7                 # 有动量时默认保留，不重新初始化

[reference]
backend = "harmonic_reference"   # 本地解析示例的 builtin 工厂

[surrogate]
backend = "harmonic_surrogate"

[policy]

numerical_floor_eV_A = 0.001

[verification]

tilt = 0.6931471805599453

[checkpoint]

keep_generations = 2

[output]
trajectory_interval_steps = 1

```

示例数字只用于开发演示，不能复制为各种材料的统一精度参数。验证参数在运行中固定；MD seed、velocity seed、check seed 和后续训练／热浴 RNG 分开管理。

期望的终端流程：

```sh
pyramid init --template harmonic --output my_run
pyramid validate my_run/run.toml
pyramid run my_run/run.toml
pyramid inspect my_run/runs/harmonic-demo --json
pyramid resume my_run/runs/harmonic-demo --steps 20
pyramid export my_run/runs/harmonic-demo --format extxyz --force-source driving --output trajectory.extxyz
```

`resume --steps 20` 明确表示额外 20 步；在帮助和日志中打印当前步及目标步。输入路径以配置文件目录为基准解析，输出目录规则固定；避免用户换 cwd 后结果写到不同位置。

Python 入口保留直接组合方式，并增加同一套 `load_config` / `run` 编排。只有 builtin 或可序列化插件可由 TOML 完整恢复；Python 自定义对象需要提供状态适配器。配置兼容性写进 schema migration，不靠宽松吞掉未知字段。

## 9. 测试与算力投入

### L0：每次提交，离线核心测试

NumPy＋ASE 的解析模型、故障注入、回调、模型代次、缓存和恢复。测试重点是用户可见行为与物理不变量；不要为 getter、薄封装或内部函数排列写大量镜像测试。核心套件目标为普通 CPU 几分钟以内，是工程目标而非已有实测承诺。

必须覆盖：

- 能量—力中心差分一致性、残余功符号、零／退化响应的处理。
- 冻结决定后检查，重试不重抽；更新后不沿用旧响应。
- 相同坐标但不同时间、质量、约束、模型／参考设置的状态判别。
- 固定原子投影及跨周期坐标；缺属性、非有限结果和不合法输入。
- 完整步 checkpoint 和新进程恢复，破损／缺失模型工件。
- 成本总账、重复事件、导出时不同来源的力。

### L1：小型可选后端集成

PySCF 分子、当地已有的 MACE 权重、QE 输出夹具和少数真实单点。网络下载、参考程序和许可证条件在测试标记中明确；缺依赖只能说明未执行，不能计为通过。保留解析核心全通过的独立状态。

### L2：云端材料工作流验收

复用已构建的软件环境，先记录一到两个参考单点的耗时，再安排 WP08。每次检查核心改变仅重跑受影响测试，避免每个小提交重算全部材料。优先在同一节点串行推进一条 MD，用该节点的核给单次 DFT 并行；不要每个 MD 步单独排一次队。

首批默认两个案例各 **不超过 100 次实际参考执行，总计不超过 200 次**。先导单点、后端一致性对照、reference-only 分支、锚点、探针、独立检查、失败重试及 restart 重复全部计入对应案例配额；不另藏一套对照成本。这是软件验收配额，非论文统计样本量。先 4–8 步估算调用结构；若全回退导致预算吃紧，先分析而非延长轨迹。WP03 的 100 步恢复对照仅使用离线解析模型，不是 100 步 DFT 任务。

以第一次实测的单参考墙钟与核数换算资源预算。需要增加配额时，报告未解决的具体验收项、预期新增调用和预计资源，由研究负责人按科学价值调整；不以“还有节点空着”为扩算理由。

使用已有 HPC provider 配置和授权环境，敏感 profile 留本地／云端。公开仓库只放通用 Slurm 模板和填写说明。单写者、MPI 环境、OMP 线程与并行探针数必须避免过度订阅。v0.4 默认探针串行，只有测得收益才加入受资源限制的并行。

### 性能报告必须区分

- 冷启动成本与可摊销成本。
- 实际参考执行、逻辑参考请求、缓存命中和独立检查。
- 有效物理时间／墙钟、CPU/GPU 资源时间、推理与训练成本。
- 力误差、功、参考调用和目标物理量的准确性。

只把参考次数减少称为“少调用参考”，不自动写成总加速。尚未做收敛测试的短轨迹，不报告收敛扩散系数等长时量。

## 10. 与下一步科研主线的接口

此前讨论的主线是：**从误差预测，推进到保守误差修正和响应复用，再判断学习算法能否带来额外的成本—精度收益。** 这一轮软件应让这些比较容易开展，而不是在工程阶段替它们预先下结论。

已有离线筛选：两个锚点、四条原轨迹的 40 个已标记构型上，同方向二次修正均降低最大原子残差，修正后／前比值中位数约 0.1593。它是同构型回顾性信号，尚不证明修正后的新轨迹、跨方向迁移或净加速。新执行者应从原记录及其哈希核对该先导结果，不把这个数作为未来实验必须达到的目标。

### 10.1 先实现一个有物理结构的非 AI 基线

设固定锚点为 X₀，位移 d=X−X₀，常数锚定力校正 c=F_reference(X₀)−F_base(X₀)，单位方向为 u，q 是残差 F_base−F_reference 在 X₀ 沿 u 的方向导数。固定当前局部段内的 c、u、q，令：

```text
B = q uᵀ + u qᵀ − (uᵀq) u uᵀ
U_corrected(X) = U_base(X) − c·d + 1/2 dᵀB d + constant
F_corrected(X) = F_base(X) + c − B d
```

B 对称且 Bu=q，因此修正能量与力一致，并抵消已知方向上的一阶残差。实现时只保存 u、q 和标量，按低秩乘法计算 Bd，不构造 3N×3N 稠密矩阵。

多方向扩展先比较对称多割线最小二乘；检查 UᵀQ 的互易性及噪声，不强行对不相容数据求精确解。Hessian 差可以不定，不能无依据强制正定。对称更新本身是经典数学工具，不应写成已经完成的原创发现。

梯度、平移／旋转处理、净力／力矩及重锚能量跳变要单独核验。局部保守性不自动保证全局动量或系综正确；必要的平滑切换必须同时作用于能量，并包含切换函数导数，不能只给修正力乘一个窗口。

### 10.2 按四个证据节点推进

1. **零新增 DFT 的交叉方向检验**：同锚点另一方向的响应用于当前路径，与常数校正、同方向二次修正和多方向割线比较。按锚点／轨迹留出，未来标签仅评分。
2. **解析前向检验**：谐振及弱非谐体系，比较同一积分步长下的误差、有效传播段、相位和总成本。展示修正真正改变后的轨迹。
3. **最小材料前向分支**：小周期体系和若干独立初态，比较当前 energetic 与保守修正，全部探针计入预算；同等精度下判断是否值得扩展。
4. **学习的额外价值**：固定数据划分，比较普通 Δ-learning、非学习响应复用、响应监督模型及不同探针选择。学习模型只在优于强简单基线时升级为主线。

### 10.3 后续 AI 模块应做什么

- 学习标量残差能量，再用梯度产生力；不能只学 C_rw 这个标量并声称重建了矢量残差。
- 学习哪些方向值得探针，目标是单位实际参考成本的有效传播收益。
- 学习旧响应何时可复用，并保留超域或模型变化后的明确失效规则。
- 为参考引擎暴露可选的电子态工件／热启动接口。先与成熟历史外推比较，不先写一个跨软件统一波函数格式。

第一版学习实验可固定基础势权重，在其可用的不变特征上训练小型标量能量修正头；若基础势不暴露合适特征，则使用独立的小模型，不让核心框架依赖某种网络内部结构。损失从能量差＋力差开始，再消融加入方向响应监督；能量偏移、按原子或按体系归一化及各项单位在训练配置中明确。Hessian-vector product 可通过自动微分计算，避免显式 Hessian；其推理和训练开销也纳入成本。

响应记忆先用有限容量的锚点集合、局部环境描述和明确的失效条件。跨构型复用向量响应时必须处理原子映射、旋转／周期分支与模型版本；相似标量描述不意味着笛卡尔向量能直接复制。先与简单近邻／割线复用比较，再考虑学习检索策略。

探针选择先做可解释的固定速度方向、正交方向、历史割线和贪心补充未解释响应四个基线；只有这些对照形成后才考虑学习策略。暂不以强化学习作为默认方案，避免训练样本成本超过待节省的 DFT 成本。

可观测量导向调度、学习传播器、空间自适应及未来自研 solver 放在同一框架的后续扩展中。不要把力误差检查界直接解释成扩散、反应率或学习传播器的准确性保证。

## 12. 执行顺序与并行分工

顺序：`WP00 → WP01 → WP02 → WP03 → WP04 → WP05 → WP06 → WP07 → WP08 → WP09`。

可并行部分：WP01 契约固定后，配置／文档与后端夹具可并行；WP02 存储契约固定后，checkpoint 与成本展示可并行。不要让多个执行者同时改 `loop/energetic.py`、Store schema 或结果类型。

建议角色边界：

- 核心执行者：时钟、状态机、checkpoint、模型切换。
- 后端执行者：ASE／QE 工厂、外部进程、parser 和后端夹具。
- 用户流程执行者：配置、CLI、示例、文档；等待稳定接口再接线。
- 独立复核者：检查冻结力、恢复、物理定义和完整成本，阅读真实结果，不只阅读实现者总结。

只有一个 coding 智能体时按上述顺序串行完成即可，不必为了形式开并行任务。第一份回报应是基线确认和 WP00 的定向修复，随后进入 WP01；不要把第一轮消耗在全仓库风格审计上。
