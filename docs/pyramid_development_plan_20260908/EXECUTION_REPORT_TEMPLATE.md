# Pyramid 开发回报模板

按工作包填写；最后一轮再填“发布完成度”。保留实际输出文件，报告只摘要关键结果。未执行写“未执行”，不能用 skip 或已有旧日志代替本轮通过。

## 本次范围

- 工作包／审阅节点：
- 基线提交、分支、当前提交：
- Python／ASE／NumPy 及有关后端版本：
- 本次解决的用户问题：
- 实际实现的功能：
- 与原计划的偏离及原因：

## 改动清单

- 路径＋主要类／函数＋修改目的：
- 新接口、配置字段和默认值：
- 旧接口／已有数据的兼容方式：
- 是否改变单位、力预算、时间、约束、随机检查或模型切换语义：

## 验收证据

对本次每个关键验收项填写：

```text
验收项：
命令／输入配置：
测试或结果文件：
预先确定的通过标准：
实际关键结果：
状态：通过 / 失败 / 未执行 / 不适用
原因与后续处理：
```

基础问题修复需说明：哪个测试能暴露原问题，修复后有什么用户可见变化。无需为了证明测试数量而给每个薄封装增加测试。

## 恢复与随机状态（相关工作包必填）

- 连续轨迹与分段恢复轨迹的长度、完整步位置：
- 是否新进程恢复：
- 位置／动量差及单位：
- route、evaluation、segment、model ID、检查抽样／计数是否一致：
- 准入前缀和检查上界是否一致：
- 故障注入位置与恢复结果：
- checkpoint 之后持久事件的重放范围、积分阶段及 RNG 后状态：
- 检查／模型更新已提交而新 checkpoint 未写入时的恢复证据：
- 重复 label／probe／update 的处理：
- 模型身份不匹配、破损快照或缺工件的处理：
- 已完成但未应用的计算如何计费、保存和复用：

## 材料与后端（相关工作包必填）

- 体系、原子数、晶胞/PBC、约束、结构来源：
- MD 算法、步长、温度初始化、时长、初态和随机种子：
- 参考程序版本、XC／dispersion、赝势身份、收敛参数和能量口径：
- 快速势版本／模型哈希、设备、精度、是否训练：
- frozen、reference-only、adaptive 等比较的设置是否一致：
- 是否实际经过接受、拒绝、检查、重新锚定、更新、恢复：
- 力／work／结构等预设检查及结果：
- 哪些能力只是接口支持，哪些完成了真实后端验证：

## 算力与成本

- 新增实际参考执行总数：
- 分用途：anchor / refusal / probe / verification / diagnostic：
- 失败尝试与重试数：
- 缓存命中和逻辑请求数：
- 由缓存标签完成的独立检查数，以及同一 evaluation 重放的去重结果：
- 参考、推理、训练、I/O 墙钟及计时口径：
- 端到端墙钟／排队时间：
- 分配 CPU 核／GPU 数、运行时长、资源时间：
- 冷启动与可摊销部分：
- 预算使用与剩余额度：

没有真实参考执行时写 0，不虚构平台数据；硬件资源未知时写未知。嵌套计时不得重复汇总。
