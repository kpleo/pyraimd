# 可直接交给实现者的任务说明

请按同目录 `DEVELOPMENT_PLAN_zh.md` 开发 Pyramid。先完整阅读计划，再按 WP00–WP09 执行，目标是交付可供材料研究人员试用的 0.4.0 候选版。WP10–WP12 是后续路线，本轮不自动执行。

Pyramid 基于 ASE 组织参考引擎、快速势、自适应 MD、误差诊断和模型更新。请复用 ASE 的结构、I/O、Calculator 和成熟算法，保留 `pyraimd2` 包及现有接口。代码应支持后续方法接入，但本轮以完成真实运行流程为准，不搭建没有实际实现的多层抽象。

- 修改软件代码及相应文档，不修改已投稿论文、投稿文件夹或旧复现数值目标。

## 第一批工作

先处理 WP00 已定位的问题：ASE 适配器中约束能量／力口径不一致；QE 默认目录复用和相对路径；密度回退仍请求文件初猜；输出成组解析与 D 指数；委员会 checkpoint recipe／长度校验；缓存前的质量／约束检查。

给每个问题补一个小而有意义的回归测试，局部修复后再进入新功能。不要先进行全仓库 lint 清扫、大规模目录重命名或与任务无关的重构。

随后按计划依次完成：

1. WP01：显式物理时钟、评估上下文、后端能力和模型身份。
2. WP02：运行／事件存储、完整成本和 energetic 检查重放。
3. WP03：完整步 checkpoint 和新进程 resume；先以冻结势和轻量有状态更新器验收，真实训练更新由 WP06 完成。
4. WP04：TOML 配置及 init/validate/run/resume/inspect/export；先跑通解析 NVE，WP05／WP07 后再验收完整后端和任务组合。
5. WP05：后端工厂、QE 可靠执行、ASE 扩展入口。
6. WP06：标签消费、模型发布、回退及更新状态恢复。
7. WP07：单点、固定模型优化、固定晶胞 NVE、FixAtoms。
8. WP08：周期体相和固定层表面两条真实材料工作流。
9. WP09：wheel 安装、用户文档、支持矩阵和候选发布验收。

## 关键实现约束

- 数值层不依赖 CLI、数据库、云端或 Torch。最小核心仍可离线使用 NumPy＋ASE 运行。
- 每次决定先冻结模型、候选力和准入，再独立抽查；检查标签只影响之后的提议。重试不重抽，接受错误不从统计分母里移除。
- 参考调用、探针、独立抽查和实际积分步是不同概念；真实物理时间不能直接等于任意 Calculator 调用数乘步长。
- 力评估数据库行不是完整步 checkpoint。恢复必须还原完整步动量、锚点／响应、准入前缀、检查 RNG、模型与更新器状态，并按原顺序重放 checkpoint 游标后的持久事件；不重新热化、不重复已完成的训练或抽样。积分阶段和完整步边界必须明确记录。
- 数值标签缓存与决策缓存分开。新接受评估照常独立抽查；可用有效精确缓存标签完成检查，正常计数而不增加 SCF 执行。同一 evaluation 的重放不重复计数。模型改变后不能把旧提议或校准用于新的评估，已用于积分子步的冻结驱动力保持原值。
- 模型更新完成记录和工件身份先持久化再激活；恢复在原边界应用已完成的更新。更新结果不明或工件不完整时停止自动恢复并报告。
- 模型切换前按旧模型结算旧 work 段。能量、力、约束投影及能量口径必须一致；未知能力不填成已支持。
- 失败、重试、probe、training、I/O 和缓存都可追溯；回滚轨迹不回滚已经消耗的实际成本。
- 通用配置中不放私有机器路径、凭据、许可受限软件或模型文件。服务器 profile 与科学输入分开。
- 改动应向后兼容。受支持能力之外的情况要明确拒绝或标明不可用，不静默降级成另一种物理计算。

## 验证方式

先运行受影响的核心测试，例如在软件检出中：

```sh
uv sync --extra dev
uv run pytest tests/unit/test_ase_adapters.py tests/unit/test_qe_engine.py tests/unit/test_energetic_loop.py tests/unit/test_store.py tests/unit/test_runner.py -q
```

根据工作包加入有意义的新测试。核心与定向测试通过后才做小后端集成；不要为普通代码改动重跑整套 DFT。运行方式如与实际项目工具链不同，请说明并采用项目已有规范。

恢复验收的“连续 100 步”对“40 步＋新进程恢复 60 步”仅使用离线解析模型，包括检查、静止坐标和模型更新边界。计数／抽样顺序严格一致，浮点误差使用预设容差；材料恢复使用短轨迹和下述配额。

云端测试复用已有环境，先测少数参考调用成本。第一批两个材料配方各至多 100 次实际参考执行，总计至多 200 次，包含先导、后端一致性、探针、对照、失败和恢复重复。配额耗尽而材料门槛未通过时，提交未通过报告并停止本批计算；需要扩展时说明具体未通过项及新增预算。不要以短轨迹声明已经实现收敛材料性质或加速。

## 回报方式和审阅节点

每完成一个 WP 使用 `EXECUTION_REPORT_TEMPLATE.md` 写一份 `WPxx_report.md`，可放在开发分支的 `docs/development_reports/` 或随回报附上。附提交 SHA、修改路径、复现命令、关键输出和未完成事项。不要贴大量未经解释的日志。

- R1：WP00–03 后提交核心契约和恢复证据。
- R2：WP04–08 后提交用户流程与两个材料案例。
- R3：WP09 后提交完整候选发布报告。

你可以在不改变科学语义的前提下自主决定常规实现细节，并继续已明确安排的工作。需要研究负责人判断的变更，单列“科学／架构决策”，同时完成其他独立工作。不要仅回复“需要确认”而不准备具体方案。

最后交付应让审阅者在干净环境中按照 README 重现运行，不依赖作者机器上的隐藏文件。WP00–09 完成后停止第一轮并回报，不自动进入新科研方向。软件测试通过、真实材料集成通过和科学加速结论是三种不同结果，请分别说明。
